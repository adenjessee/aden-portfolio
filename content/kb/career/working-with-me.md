title: Working with me
---

Working with me as a teammate means I write things down. Before a large change I write a short plan: what I intend to change, what it touches, and how we will know it worked. After the change, the pull request says what I verified and what I did not.

In code review, I review the way I want to be reviewed. I read the change against the structure of the system, ask what else it reaches, and name the one thing I would change first. At GridSchool every written review ends as accepted or sent back with that one thing, so the author always knows the next step. I try to keep review comments about the code and the evidence.

My communication style is direct and plain. If I think a plan has a problem, I say so early and say why. If I am wrong, I want to hear it with the reason, and I change my mind when the evidence is better than mine. I prefer async written updates for most things and a short call when a decision is stuck.

On disagreements, I ask what evidence would settle the question, then go get it. A failing test, a graph of the change, or two numbers side by side usually ends an argument faster than more discussion.

For teams using AI coding agents, I hold agent output to the same review standard as human output. I am happy to help a team set up the checks that make agent changes safe to accept: tests that would catch the defect, structural context for the agent, and budgets on what it can spend.

On ownership, when I take something on I see it through to production and keep watching it after it ships. If I cannot finish something, I say so early.
